# Развёртывание на Railway

Разворачивается **панель** — веб-приложение и его командная строка. Рабочие процессы
(захват видео, детекторы, распознавание лиц) на Railway не разворачиваются и не могут: им
нужен доступ к камерам школы по RTSP и видеокарта, а Railway не даёт ни того, ни другого.
Панель это переживает честно — камеры показываются со статусом «офлайн», а не молча.

Разбор уроков от этого не страдает: он и так делается **заранее, вне сети**, отдельным
пакетом `classvision`, а его результат приходит в панель командой `qorgan classvision
import`. Именно поэтому кабинет психолога на Railway работает полностью.

---

## 1. Что уже готово в репозитории

| Файл | Где лежит | Что делает |
|---|---|---|
| `Dockerfile` | **корень репозитория** | Образ панели: Python 3.11-slim, без torch, без ultralytics, **без opencv** |
| `railway.json` | **корень репозитория** | Сборка через Dockerfile, health-check на `/healthz` |
| `.dockerignore` | **корень репозитория** | Не пускает в образ фотографии детей, записи, секреты, `data/` и весь `classvision/` |
| `deploy/requirements-web.txt` | `qorgan-ai-main/` | Точный список зависимостей панели, и почему из него убран opencv |
| `deploy/railway-entrypoint.sh` | `qorgan-ai-main/` | Порт, том, миграции, первичная учётная запись — в этом порядке |
| `.env.railway.example` | `qorgan-ai-main/` | Шпаргалка по переменным окружения |

> **Почему Dockerfile лежит в корне, а не рядом с пакетом.** В репозитории два пакета, и
> Railway собирает из корня. Пока `Dockerfile` и `railway.json` лежали внутри
> `qorgan-ai-main/`, платформа их не находила, передавала сборку автоопределителю и падала:
> «Railpack could not determine how to build the app» — он видел две папки, README и
> .gitignore. Теперь настраивать Root Directory в интерфейсе не нужно: репозиторий
> разворачивается как есть. Контекст сборки — корень, поэтому все `COPY` в Dockerfile
> написаны от него, а `classvision/` исключён `.dockerignore` целиком.

Образ **собран и проверен локально**: 437 МБ, контейнер стартует, миграции проходят,
вход работает, база ложится на том.

## 2. Порядок действий

### 2.1. Создать сервис

```bash
npm i -g @railway/cli
railway login
railway init          # из КОРНЯ репозитория, не из qorgan-ai-main
```

Если сервис уже создан и падал на `Railpack could not determine how to build the app` —
достаточно затянуть текущий `main`: `Dockerfile` и `railway.json` теперь в корне, и
автоопределитель больше не задействуется. Root Directory в настройках сервиса оставьте
пустым.

### 2.2. Подключить том — **до первого развёртывания**

Railway → ваш сервис → **Data** → **Add Volume**, точка монтирования:

```
/state
```

Без тома база и медиа лежат в слое контейнера и **исчезают при каждом развёртывании**
вместе со всеми учётными записями и разборами. Точка входа это проверяет и отказывается
стартовать, а не делает вид, что всё хорошо.

### 2.3. Задать переменные

Railway → **Variables**. Минимум:

```
SECRET_KEY=<python -c "import secrets; print(secrets.token_urlsafe(48))">
QORGAN_ENV=prod
WEB_HTTPS=true
QORGAN_STATE_DIR=/state
BOOTSTRAP_ADMIN_USER=admin
BOOTSTRAP_ADMIN_PASSWORD=<длинный пароль>
```

`PORT` и `WEB_HOST` **задавать не нужно**: первый приходит от платформы, второй ставит
точка входа. Полный список с пояснениями — в `.env.railway.example`.

> **`WEB_HTTPS=true` — это не галочка, а утверждение.** Railway терминирует TLS на своём
> краю, поэтому здесь это правда. Флаг решает единственное: помечается ли сессионная
> cookie как `Secure`. Поставить `true` и раздавать по голому `http://` — вход зациклится,
> потому что браузер не вернёт cookie. Это проверено: локальный контейнер с
> `WEB_HTTPS=true` по `http://` отдаёт **403 на вход**, и это правильный отказ.

### 2.4. Развернуть

```bash
railway up            # из корня репозитория
```

Сборка проверена локально из того же корня: образ 433 МБ, контейнер стартует, миграции
проходят, вход работает, база и медиа ложатся на том.

### 2.5. Первый вход и сразу после него

Зайдите под `BOOTSTRAP_ADMIN_USER`, затем **удалите обе переменные `BOOTSTRAP_*` из
Variables**. Пока они там, пароль администратора лежит в настройках проекта открытым
текстом. Учётная запись создаётся только когда таблица пуста — повторные развёртывания
её не пересоздают и пароль не меняют.

## 3. Загрузить данные школы

Всё это — разовые команды через `railway run`, которые попадают в тот же код, что и панель:

```bash
railway run qorgan classvision import /path/to/analysis.json
railway run qorgan classvision status
```

Реестр учеников и фотографии на Railway загружать **не следует**: это персональные данные
детей, а сервис — демонстрационный стенд. Кабинет психолога работает и без них: места
показываются как места, пока школа не подпишет план рассадки.

---

## 4. Что НЕ будет работать, и почему это правильно

| Что | Почему | Что видно в панели |
|---|---|---|
| Живые кадры камер | Нет RTSP до школы | Плитки «офлайн», серый значок |
| Детекция буллинга и оружия | Нет рабочих процессов и видеокарты | Пустые списки с объяснением |
| Столовая | Нет камеры на входе | Пустой журнал |
| Telegram | Не настроен | Тревоги пишутся, но не отправляются |

Ни одна из этих страниц не притворяется работающей — каждая говорит, чего ждёт. Это
проектное решение, а не следствие развёртывания.

## 5. Обновление стилей

Оформление собирается Tailwind в **закоммиченный** файл. На Railway сборки стилей нет и
Node не нужен:

```bash
npm ci
npm run css          # src/qorgan/web/tailwind.css → src/qorgan/web/static/app.css
```

После правки стилей перенесите копию в статическую выгрузку кабинета (она вшита в
`classvision/cabinet/skin.py` и проверяется тестом `test_cabinet_skin.py`).

## 6. Проверка после развёртывания

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://<ваш-домен>/healthz   # 200
```

Логи первого запуска должны содержать, по порядку:

```
миграции: alembic upgrade head
создана первая учётная запись: admin (admin)
запуск панели на 0.0.0.0:<PORT> (QORGAN_ENV=prod)
```

Если вместо этого написано «ОТКАЗ: /state не смонтирован» — вернитесь к шагу 2.2.
