# classvision — модуль «Класс»

Разбор записи урока: сколько раз ученик поднимал руку, вставал, отворачивался назад,
лежал на парте, был вне своего места — по каждому **месту** в классе, с накоплением по
неделям для кабинета психолога.

**Система не ставит диагнозов.** Она считает наблюдаемые факты и рядом с каждым числом
показывает, сколько времени она вообще видела это место. Решение принимает человек.

---

## Что это умеет и чего не умеет

| Требование заказчика | Статус |
|---|---|
| распознать людей, вести трекинг | ✅ YOLO11m-pose + ByteTrack, 9–10 человек в кадре, conf 0.85–0.94 |
| сидит / вовлечён / лежит на парте / смотрит назад | ✅ как **наблюдаемые позы**, не как вывод о состоянии ребёнка |
| стоит у доски | ⚠️ только если задана зона доски. На этой камере доска **позади объектива** |
| «поднимал руку, **отвечал**» | ⚠️ рука — да; **ответил вслух — нет**: в файле нет аудиодорожки (`nb_streams=1`) |
| динамика снижения активности **внутри урока** | ✅ `metrics/within_lesson.py`: урок режется на 6 равных отрезков, индекс и все его составляющие считаются заново на каждом, место сравнивается **только само с собой** |
| динамика снижения активности **по неделям** | ⚠️ `metrics/trend.py` построен и сравнивает ученика **только с самим собой**, но на имеющихся данных ОТКАЗЫВАЕТ: нужно ≥5 уроков и подтверждённая личность на месте, а есть по одному уроку с двух разных камер |
| накопление в кабинете психолога | ✅ контракт интеграции — `INTEGRATION.md` |
| анализ учителя | ✅ построен, но **выключен по умолчанию** (см. ниже) |

Про учителя: метрики положения (сколько сидел, сколько стоял, сколько вне кадра) считаются,
но в `qorgan-ai-main` по умолчанию не импортируются — школе письменно обещали, что оценки
работы учителя не будет (§12.5). Это решение школы, а не инженера; флаг `--teacher`.

---

## Главная идея: единица учёта — **место**, а не трек и не лицо

| кандидат | почему не подходит / подходит |
|---|---|
| трек (ByteTrack id) | умирает на первом заслоне; за урок один ребёнок становится несколькими треками |
| лицо | лица тут крупные (медиана **64 px**, а не 11,5 px как в коридоре), но совпадение по галерее из 141 фото — медиана **0,30 при отрыве 0,10**. Это предпочтение, а не опознание |
| **место** | ребёнок сидит на одном месте весь урок и весь семестр; место переживает заслон и не путается при пересечении |

Места **находятся автоматически** по самой записи (DBSCAN в пространстве, выпрямленном по
перспективе). Имя к месту привязывается **только** из подписанного плана рассадки
(`identity/seatmap.py`). Пути «из эмбеддинга лица в фамилию» в коде нет.

Полные измерения — `MEASUREMENTS.md`.

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[analyse]"          # + [faces] и [llm] по желанию
```

Работает на Apple Silicon (MPS) без CUDA. Веса YOLO скачиваются при первом запуске —
для школы без интернета их нужно положить рядом заранее.

## Запуск

```bash
classvision analyse test_camera.mp4 --sample-fps 2 --out out/lesson.json
```

```bash
classvision report out/lesson.json --out out/report
```

```bash
classvision seatmap-template out/lesson.json --camera camera01 --class 3-Б --out seatmap.yaml
```

```bash
classvision analyse test_camera.mp4 --seat-map seatmap.yaml --roster roster.csv --photos student_photos
```

```bash
classvision verify out/lesson.json --from 1020 --to 1080 --out out/verification.mp4
```

Последняя команда — **главная проверка**: разметка рисуется поверх исходного видео.
`overlay.agrees_with_artefact()` дополнительно доказывает, что разметка на видео и числа в
отчёте получены одним и тем же расчётом (сейчас: 0 расхождений на 8 местах).

### Разметка комнаты: `--room`

Зона доски и стол взрослого — единственное, что о комнате утверждает **человек**, а не
измерение. Поэтому они лежат отдельным файлом на камеру, в `configs/`, попадают в
`provenance.room.layout` артефакта и входят в `run_id`: подвинули полигон — это новый
прогон, а не тихая переписка старого.

```bash
classvision analyse D14_20260815103136.mp4 --room configs/camera_d14.yaml
```

Профилей в репозитории ровно два, и это документ, а не пример:

| профиль | доска в кадре | `board_zone` |
|---|---|---|
| `configs/camera_d14.yaml` | да, зелёная трёхсекционная, x 1024..1603 | шестиугольник с вырезом над учительским столом |
| `configs/camera_01.yaml` | **нет**, камера висит над доской | `null` + написанная причина |

**Зона проверяется по ЛИНИИ ПЛЕЧ, а не по ступням.** Отсюда самая частая ошибка разметки:
нарисовать зоной доски полосу ПОЛА перед доской. Полигон при этом получается совершенно
правильный — люди действительно там стоят, — но линия плеч в него не попадает никогда, и
«у доски» остаётся нулём всё время работы, причём `lesson.unmeasured` про это молчит: зона
ведь задана. Поэтому вместе с `board_zone` обязателен `board_surface` — прямоугольник самой
доски; загрузчик сверяет одно с другим и отказывается загружать профиль, где зона не
пересекается с доской. Почему по плечам, с числами — `MEASUREMENTS.md` §12.

Проверять разметку глазами — отдельная команда, потому что четыре пары чисел на глаз не
читаются:

```bash
classvision zones D14_20260815103136.mp4 --room configs/camera_d14.yaml \
    --at 1764 --out out/zones_d14.jpg --expect-in-board 1
```

Кадр 1764 с — тот, где один ученик стоит у доски, а взрослый сидит **среди учеников**:
профиль, который различает эти два случая, различает главное. `--expect-in-board`
превращает команду в регрессию (выход `1` при расхождении).

Четыре случая, три кода выхода, и различие между двумя нулями — не формальность:

| выход | что произошло |
|---|---|
| `0` | зона доски задана, и в кадре нашлось столько людей у доски, сколько ожидалось |
| `0` | у камеры `board_zone: null` — измерять нечего, и ноль здесь не находка |
| `1` | зона задана, но у доски никого; если кто-то стоял — разметка неверна |
| `2` | задан `--expect-in-board` для камеры без зоны доски: проверять не на чем |

### Кабинет: накопление по неделям

Всё выше — про один урок. Заказчик просил другое: «эта вся аналитика копится в кабинете
психолога… первая неделя хорошо, вторая неделя не очень». Это `cabinet/` — файл SQLite
(стандартная библиотека, без ORM) и статический HTML:

```bash
classvision cabinet import out/*.analysis.json --room-key camera01 --class 3-Б
classvision cabinet show   --room-key camera01 --class 3-Б
classvision cabinet weekly  --room-key camera01 --class 3-Б
classvision cabinet lessons                      # что сравнимо МЕЖДУ записями
classvision cabinet report --out out/cabinet
classvision cabinet attest --place-id 3 --external-id student_53 \
        --by "Иванова И.И., классный руководитель" --at 2026-09-01 \
        --valid-from 2026-09-01 --valid-to 2026-12-31 --decision "Протокол №14 от 28.08"
```

Четыре вещи, которые эта часть делает и которых нет в артефакте одного урока:

* **Один ключ класса на две комнаты — это не один класс, и кабинет об этом кричит.** Две
  разобранные записи, которые у нас есть, сняты РАЗНЫМИ камерами (camera01 — 8 ученических
  мест, D14 — 5), в разные недели, без подписанного плана рассадки. Артефакт не знает ни
  комнаты, ни класса, поэтому без `--class` обе ложатся под ключ `-` — и обзор, который
  расставляет их рядом, за одну секунду читается как «первая неделя хорошо, вторая не
  очень» про один класс. Динамика между ними не строится нигде (её условия — пять
  собственных уроков ученика и подписанное место), но этого мало: предупреждение
  печатается на всех 21 странице, собирается из ключей и дат самой базы и исчезает само,
  как только ключи разведут. Сравнимо между такими записями только то, что относится к
  САМИМ ЗАПИСЯМ — видимость, число найденных мест, события по комнате, положение
  взрослого; для этого есть отдельная страница `lessons.html` и команда `cabinet lessons`,
  и на ней у каждого столбца написано, чем он НЕ является.

* **`seat_id` — не ключ между уроками.** Номера мест раздаются сортировкой по порядку
  чтения, поэтому один отсутствующий ученик сдвигает все номера за собой. Между уроками
  места сопоставляются **по геометрии** — с порогом и с запасом до второго кандидата
  (`INTEGRATION.md` §2a). На реальных данных: 9 мест создано по первой записи, 9 из 9
  узнано во второй; сдвиг камеры на 600 px даёт 0 узнанных и 9 новых мест, а не молча
  унаследованную историю.
* **Два файла одного часа — отказ, а не удвоенный урок.** `clip_15min.mp4` — это вырезка
  из `test_camera.mp4`; хэши разные, час один. Импорт отказывает по пересечению часов.
  Отдельно распознаётся разрыв записи регистратором: у пары D14 первый файл начинается в
  10:17:59 и длится 818 с, то есть кончается в 10:31:37, а второй начинается в 10:31:36 —
  шов выглядит как пересечение на секунду, потому что оба времени известны с точностью до
  секунды. Это два файла и **одно занятие** — в любом порядке загрузки: шов ищется в обе
  стороны. Раньше искался только назад, и та же пара, загруженная длинным файлом вперёд,
  молча становилась двумя занятиями (`MEASUREMENTS.md` §9.4).
* **Отказ строить динамику — это состояние страницы, а не пустой график.** «Данных пока
  мало: 1 урок из 5», «место не подписано», «уроки без даты» — три разных ответа с тремя
  разными действиями, и каждый показан вместе со списком условий (выполнено / нет).

Повторный импорт того же артефакта — ничего не пишет. Повторный **разбор** того же видео с
другими порогами — новый прогон, который сохраняется и **не заменяет** прежний; переключить
расчётный прогон можно только отдельной командой `cabinet select-run`.

### Записка-ориентир: единственное место, где работает языковая модель

```bash
classvision cabinet note --all                     # или: cabinet note <run_id>
classvision cabinet note --all --backend deterministic   # не обращаться к модели вовсе
```

Короткий русский абзац о том, **с чего начать чтение отчёта** — не пересказ чисел. Проверка
(`report/orientation.py`) отклоняет в тексте любую цифру, кроме номера места, и отклонённая
записка не показывается вовсе: величина в ней невозможна по построению, поэтому и
перепутать её с другой величиной нельзя (`MEASUREMENTS.md` §8 — про то, как это выглядело,
когда было можно). Записка хранится рядом с тем **прогоном**, о котором написана: разбор
заново с другими порогами — другое измерение, и старая записка к нему не переносится.

**Что уходит наружу:** 2 286 байт по уроку D14 и 3 261 байт по уроку камеры 01 — измерено,
это счётчики по местам и доли видимости. Ни кадров, ни имён, ни дат, ни ключей комнаты и
класса, ни координат (`cabinet/notes.py`, там же разбор вопроса ЗРК 94-V).

**Ноль в сводке различается трижды, и это главное, что защищает записку от неправды**
(`MEASUREMENTS.md` §13.8):

* счётчик, который эта камера измерить не может, уходит как `null`, а не как ноль — на
  камере 01 доска за объективом, и ноль «выходил к доске» тут свойство объектива;
* то же самое, когда запись **противоречит собственному нулю**: на D14 доска в кадре, но у
  доски кто-то стоял половину урока, а по ученическим местам «выходил к доске» — ноль,
  потому что «у доски» это состояние МЕСТА, а ребёнок к доске со своего места уходит;
* ноль, который значит «эпизода нужной длины не набралось», помечается отдельно от нуля,
  который значит «не было вовсе»: на месте 8 камеры 01 голова опускалась на парту
  75 секунд, а счётчик эпизодов — ноль. Про такой счётчик записке разрешена ровно одна
  формулировка — «длительных эпизодов не отмечено».

Без ключа команда не падает, а так и говорит; страница в этом случае пишет, почему записки
нет, и что нужно, чтобы она появилась. Если ключа нет, а записка уже была, она **остаётся**,
и в журнале печатается «НИЧЕГО НЕ ОТПРАВЛЕНО» — про сегодняшний запуск, а не про тот, в
котором её написали. Записки по классу целиком нет — и это решение с
обоснованием, а не пропуск: см. `notes.CLASS_NOTE_REFUSAL_RU`.

## Как это устроено

```
video/clock.py      вшитые часы камеры → реальное время (13/13 кадров верно, дрейф 0,2 с за 52 мин)
video/decode.py     последовательный декод, 583 fps — декод не узкое место
vision/pose.py      YOLO11m-pose, imgsz 1280 (0,109 с/кадр на M2 Pro)
room/perspective.py выпрямление перспективы: ширина плеч 19–232 px → один порог на весь кадр
room/seats.py       DBSCAN → места; порог выбирается по совпадению с числом людей в кадре
room/zones.py       кто из них взрослый (по масштабу или по заданной зоне)
geometry.py         чистая геометрия COCO-17, всё в долях ширины плеч
states.py           поза → состояние, пороги из измеренных распределений
ledger.py           наблюдения → эпизоды (удержание + пауза), с учётом непросмотренного
metrics/            индекс активности (разложенный), динамика, метрики учителя
identity/           реестр, план рассадки, лица (только как подтверждение), стандарт доказательства
report/             JSON-артефакт, графики, HTML, русская сводка, проверочное видео
cabinet/            накопление многих уроков: SQLite-хранилище, недели, динамика, HTML-кабинет
integration/        что именно импортирует qorgan
```

Расчёт двухпроходный: тяжёлый проход (модель) кэшируется, поэтому **пересчёт с другими
порогами занимает 5–7 секунд** вместо 15 минут. Это и делает пороги обсуждаемыми.

## Дисциплина, которой подчинён весь код

1. **Ни одно число не показывается без покрытия.** Место, видимое 70 % урока, и место,
   видимое 100 %, дают несравнимые счётчики.
2. **«Не удалось измерить» — это результат**, а не пропуск. У каждого прогона есть список.
3. **Ноль и «не смотрели» — разные значения.** Где камера не видела, стоит `unknown`.
4. **Каждая выбранная константа помечена CHOSEN** прямо рядом с собой, с обоснованием.
5. **Повторный расчёт с другими порогами — другой отчёт** (другой `run_id`), а не правка старого.
6. **Ребёнок сравнивается только с собой.** Рейтингов класса нет и не будет.

## Тесты

```bash
PYTHONPATH=src ../.venv/bin/python -m pytest tests/ -q
```

Все проходят; 66 из них — накопительный слой (`tests/test_cabinet.py`). Тесты, которым
нужна запись, аккуратно пропускаются, если её нет — видео в репозиторий не попадает
(`.gitignore`).

Что закреплено тестами: чтение вшитых часов на 13 кадрах с известным временем; линейность
часов; геометрические предикаты на синтетических позах, включая **оба найденных дефекта**
(учитель за ноутбуком, засчитанный как поднятая рука, и «пустая комната» при отсутствии
независимой оценки числа людей); выпрямление перспективы; поиск мест на реальном уроке
(ровно 9); имена полей артефакта (см. ниже про схему 1.1); и главное — что **проверочное
видео воспроизводит отчёт до последнего наблюдения**.

По кабинету: повторный импорт ничего не пишет, а повторный импорт **с другим ключом
комнаты — отказывает**, а не молчит; повторный разбор не заменяет прежний;
сдвинутая камера создаёт новые места, а не наследует чужую историю; разорванная
регистратором запись собирается в одно занятие **при любом порядке загрузки файлов**;
неделя без уроков несёт `None`, а не ноль; место без накопленных занятий не показывает
нулей; взрослый, которого не удалось найти в кадре, **перечислен, а не пропущен**; у
взрослого нет ни индекса, ни динамики; и — главное — **занятие
из одного файла воспроизводит индекс артефакта до десятой доли по всем восьми местам**,
потому что кабинет пересчитывает индекс той же `metrics/activity.py` по сумме журналов, а
не усредняет готовые числа.

## Сводка на естественном языке

Отчёт всегда содержит детерминированный русский текст — он и есть запись. Каждое число в нём
проверяется программно против исходных данных (сейчас: 364 числа, все подтверждены).

LLM (Gemini) подключается **сверху** и работает по правилу: **модель выбирает, что важно, и
объясняет словами, но ни одного числа не печатает сама** — числа подставляет код из данных.
Так переприписать число к чужому утверждению структурно невозможно.

Почему именно так — `MEASUREMENTS.md` §8: при первом тесте Gemini прошёл проверку чисел
(350 из 350 подтверждены) и всё равно выдал ложное утверждение, склеив долю 96,5 % с
длительностью от другой величины. Проверка сверяет, что число **существует**, а не что оно
относится к нужному утверждению.

## Что честно не сделано

* Ни один порог **не проверен на размеченном человеком уроке**. Все они выведены из
  распределений на этой записи. План минимальной разметки — в `MEASUREMENTS.md`.
* Направление головы определяется грубо (какое ухо видно), а не по углу.
* **Динамика ВНУТРИ урока показана на обеих реальных записях; динамика ПО НЕДЕЛЯМ — нет.**
  Внутриурочная: из 13 ученических мест двух уроков направление установлено у двух (место 4
  камеры 01 — −25,3 балла, p = 0,017; место 8 — −5,4, p = 0,056), у одного оно нашлось только
  в составляющей (место 7, «голова поднята» −21,4 балла, p = 0,056, при том что индекс целиком
  «не установлено»), остальные — «менялось не в одну сторону» или «меньше порога». Шесть
  «снижений», которые засчитало бы наивное чтение, свелись к одному, и каждое отпало по своей
  причине — разбор в `MEASUREMENTS.md` §14.5.
* **Динамика по неделям не продемонстрирована на реальных данных, и это не оговорка.**
  `metrics/trend.py` требует ≥5 разобранных уроков одного ученика; в наличии два дня съёмки
  с двух камер — по одному занятию на класс. Накопление, недели, счётчики и сопоставление
  мест между уроками работают и проверены; сама ДИНАМИКА в кабинете сейчас показывается как
  состояние «данных пока мало: 1 урок из 5», и это честный ответ, а не сломанная страница.
  Расчёт динамики закреплён отдельным тестом на пяти синтетических уроках, который
  прогоняет через кабинет ту же самую `metrics/trend.py` и сверяет результат один в один.
